# 계약가이드 MVP

공공기관 계약 담당자가 조건(기관, 계약 유형, 추정가격, 상대방, 희망 계약 방법, 긴급·특수 사유)을 선택하면
계약 절차와 관련 법령(원문)을 안내하고, 추가 질문에는 저장된 조문을 근거로 답하는 웹 서비스입니다.

- 법령 범위: 국가계약법·지방계약법 (공공기관은 준비 중)
- 법령 확인 기준일: 2026-11-02 (법제처 국가법령정보센터 원문 직접 확인)
- AI와 법제처 API는 아직 연계하지 않았습니다. 규칙과 저장된 조문만으로 동작합니다.

## 1. 실행 (Node.js 18 이상, 설치 패키지 없음)

`시작.bat`을 더블클릭하거나 터미널에서 다음을 실행합니다.

```
cd 계약가이드_MVP
npm start
```

브라우저에서 http://localhost:3000 을 엽니다.

## 2. 팀원과 공유하기

1. 서버를 켠 PC의 터미널에 "같은 네트워크 팀원: http://192.168.x.x:3000" 주소가 표시됩니다.
2. 같은 와이파이/사내망의 팀원이 그 주소로 접속합니다. 처음 실행할 때 Windows 방화벽 허용 창이 뜨면 "허용"을 누르세요.
3. 결과 화면의 "링크 복사"로 조건이 담긴 주소를 팀원에게 보낼 수 있습니다.
4. 다른 네트워크의 팀원과 공유하려면 다음 중 하나를 사용합니다.
   - 터널 서비스(ngrok, cloudflared 등)로 임시 공개 주소 만들기
   - Render, Railway 같은 서비스에 배포하기 (Node 서버 그대로 배포, 시작 명령 `npm start`)
5. 인터넷에 공개할 때는 `ADMIN_KEY` 환경변수를 설정하세요. (관리자 화면 보호)

```
set ADMIN_KEY=원하는비밀번호
npm start
```
관리자 화면: http://localhost:3000/admin.html?key=원하는비밀번호

## 3. 화면과 기능

| 기능 | 설명 |
|---|---|
| 조건 선택 | 기관, 계약 유형, 공사 종류, 추정가격(만원), 상대방, 희망 계약 방법, 긴급·특수 사유 |
| 판정 | 수의계약 근거 해당 여부, 근거 조문(호·목)과 금액 기준 |
| 절차 | 단계별 설명. "조문 확인"은 원문 근거가 있는 단계, "일반 안내"는 근거 확인 전 단계 |
| 필요 서류 | 체크리스트 (일반 안내) |
| 관련 법령 | 조문 원문, 시행일, 확인일, 법제처 링크 |
| 추가 질문(챗봇) | 질문 버튼, 자유 질문(FAQ -> 캐시 -> 조문 검색 -> 유권해석 검색 -> 근거 없음). 조문·FAQ 답변에는 관련 유권해석을 함께 붙이고, 분야별 유권해석 목록·상세·매뉴얼 원문 쪽 보기를 제공 |
| 피드백 | 답변별 "도움이 되었나요", 전체 의견 |
| 관리자 | 사용 통계, 질문 기록(근거 없는 질문 = FAQ 후보), 피드백 |

## 4. 폴더 구조

```
server.js            서버 (API + 정적 파일)
lib/engine.js        계약가이드 엔진 (규칙 + 조문 -> 절차·근거)
lib/chat.js          추가 질문 처리 (FAQ, 캐시, 조문 검색)
lib/store.js         통계·질문·피드백 기록 (runtime 폴더)
data/                내용 데이터 (JSON, 코드 수정 없이 편집)
public/              화면 (index.html, app.js, style.css, admin.html)
test/                자동 테스트 (npm test)
runtime/             실행 중 기록 (자동 생성, git 제외)
```

## 5. 내용 수정 (data 폴더, 서버 재시작 불필요)

| 파일 | 내용 |
|---|---|
| data/rules.json | 수의계약 근거 규칙 (금액 범위, 상대방, 근거 조문), 긴급·특수 사유 |
| data/articles.json | 조문 원문 (법령명, 조문, 시행일, 확인일, 링크, 검색 키워드, 본문) |
| data/procedures.json | 조문 근거 없는 일반 단계와 필요 서류 목록 |
| data/notes.json | 주의사항 (조건부 표시 가능) |
| data/faq.json | 저장 답변 (질문 버튼, 키워드, 기관별 답변, 근거 조문) |
| data/options.json | 조건 선택지 |
| data/interpretations.json | 유권해석 113건 (『2026년 지방계약 실무 매뉴얼』 제7장 제1절, 313~371쪽). PDF에서 기계적으로 옮겼으므로 띄어쓰기가 어긋날 수 있어 답변마다 원문 쪽 이미지(public/manual/m313~m371.jpg)를 연결함. 국가기관 질문에는 쓰지 않음 |

수정 후 브라우저를 새로고침(F5)하면 반영됩니다. JSON 문법(쉼표, 큰따옴표)을 틀리면 화면에 오류 안내가 나옵니다.

### 규칙 추가 예시 (rules.json)
```json
{ "id": "L-GS-NEW", "org": "loc", "types": ["goods","service"], "partner": "smallbiz",
  "minAmount": 2000, "maxAmount": 10000, "law": "LOC-ENF-25",
  "ref": "제25조제1항제5호라목", "text": "화면에 표시할 설명" }
```
금액 단위는 만원, minAmount는 초과, maxAmount는 이하입니다. law는 articles.json의 id입니다.

### 조문 추가 방법 (articles.json)
법제처에서 조문을 복사해 항목을 추가합니다. `keywords`에는 사용자가 물어볼 만한 단어를 넣으면 질문 검색이 정확해집니다.
엔진이 새 조문을 절차 단계에 연결하려면 lib/engine.js의 단계 생성 부분(refs)도 함께 수정해야 합니다.

## 6. 법령 개정 시 할 일
1. 법제처에서 개정된 조문을 확인합니다.
2. articles.json의 본문, 시행일(effective), 확인일(verified)을 고칩니다.
3. rules.json의 금액·조건, faq.json의 답변을 고칩니다.
4. `npm test`로 기대값을 확인하고, 바뀐 기준에 맞게 테스트를 고칩니다.

## 7. 아직 연계하지 않은 것 (다음 단계)
- 법제처 Open API: 조문 자동 수집·개정 감지 (현재는 원문을 직접 확인해 articles.json에 저장)
- AI 모델: 저장 답변·조문 검색으로 답하지 못한 질문 처리.
  근거를 찾지 못한 질문의 응답에 `ai.payload`(조건 코드, 규칙 ID, 후보 조문 ID, 질문)를 이미 만들어 두었으므로,
  이 payload를 모델에 전달하는 부분만 lib/chat.js 마지막 단계에 추가하면 됩니다.
- 공공기관(공기업·준정부기관) 기준, 계약보증금·입찰보증금·낙찰자 결정 방식 등 나머지 절차 조문
- 로그인, 데이터베이스 (현재는 runtime 폴더의 파일에 기록)
- 유권해석 분야와 계약 단계(engine 단계 key) 연결, 매뉴얼 개정 시 data/interpretations.json 재추출

## 8. 한계
- 일반 안내로 표시된 단계와 서류는 조문 근거를 확인하지 않았습니다.
- 수의계약 판정은 금액·상대방 요건 중심이며, 각 호·목의 세부 요건은 원문 확인이 필요합니다.
- 참고용이며 공적 견해표명이나 유권해석이 아닙니다.
